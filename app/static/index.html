Source → claim → metric

Evidence Engine

Tavily searches are governed by an editable criteria registry. Search hits become immutable source evidence, then review-required claims. Only verified or manually confirmed claims can enter a production calculation.

Tavily search criteria

Use the registry as the collection control plane. Collection is manually initiated and preserves request, usage, source, and review records.

Evidence policy

No source, no score.

1. Retrieve
Raw Tavily result retained with canonical URL, relevance, publication date, content hash, and collection run.
01
2. Normalize
Deterministic code canonicalizes URLs, dates, stage labels, amounts, and heterogeneous source formats into one document contract.
02
3. Enrich
The LLM maps the normalized document to the controlled ontology and separates source-fact candidates from model inferences.
03
4. Validate
Deterministic checks compare amounts, stages, names, literal quotes, taxonomy membership, and duplicate fingerprints with the source.
04
5. Admit
Only reviewed source facts enter the trusted graph. Accepted model inferences enter separately with dashed inference semantics and provenance.
05
6. Calculate
Each metric snapshot persists formula version, time window, source claim IDs, denominator safeguards, and status.
06
Collection prerequisite. Add a real Tavily key to .env. The bundled engine performs no live search until you explicitly run a collection.
Direct structured APIs

Builder flow + capital evidence

GitHub collects public repository metadata and activity for Builder Flow. SEC EDGAR collects filing and company-fact evidence for Capital Flow. Both use the same source, claim, review, metric, and Neo4j pipeline as Tavily.

Interpretation layer

LLM classifies; it does not verify.

The controlled ontology enricher extracts capital events and classifies technology, application, buyers, pain points, and dependencies. Explicit source facts require literal support; inferred dependencies remain separate model inferences.

Default model: gpt-5-mini is selected for cost-efficient structured extraction. Set LLM_ENABLED=true and configure an OpenAI-compatible key only when ready to run it.
Review queue

Claims awaiting verification

Validation checks candidate facts against the normalized source before review. Verified source facts and accepted model inferences are stored with different provenance and cannot be confused in the graph.

Exact metric snapshots

Formula-backed calculations

The engine now implements Capital per Builder, original multiplicative Opportunity, Picks & Shovels, Pain Density, Pain Opportunity, Downstream Dollar, and House Edge. No number appears if its required verified evidence is missing.

Formula definitions are versioned. The calculation endpoint exposes each exact formula and every snapshot supports an evidence drill-down. This interface is intentionally conservative: a market with missing verified inputs is labelled insufficient_evidence, not assigned a synthetic score.
